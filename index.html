Principles we work to

Every feature has a cost. Earn trust through depth, polish, and reliability — not feature count.

Bug fixes name the mechanism before the patch. A stopgap is allowed but never silent: every fix PR carries Root cause: and Fix type: lines, and a stopgap’s follow-up ticket must exist before merge.

docs/decisions/0019-root-cause-first-bug-fixing.md

No handoff culture. Designers, engineers, and agents share ownership from idea to implementation. We are all builders.

Conventions live in Agent Skills that load on demand, so a human and an agent read the same rules from the same file instead of one inheriting the other’s summary.

.agents/skills/ · AGENTS.md

Plant deliberately. Prune relentlessly. Every change should make the system simpler, stronger, or more useful.

SwiftLint and Periphery are baseline-ratcheted: new violations and new dead code fail CI, and deleting code means regenerating the baseline. Debt can hold, but it cannot grow.

make lint · make periphery

Systems scale. Screens don’t. Design components, states, and flows that can be reused across the product.

Check the component catalogue before building a new control. Where a shared component already exists it wins — production switches are HeidiToggle, not a bespoke toggle.

docs/design-system-component-catalog.md

The product is the truth. Figma communicates intent, but the design system lives in production code.

This site has no hand-written values. Every number, hex and glyph on it is parsed from the Swift sources at build time, so it cannot describe a system the app doesn’t have.

HeidiNative/Common/Theme/

Every inconsistency compounds. Shared patterns and behaviors create products that feel reliable and trustworthy.

One spelling per job. A token names what it paints — surface, fill, foreground, border — so the same intent resolves to the same value everywhere, in both themes.

HHColors.swift

Start with the platform. Custom UI should solve a real problem, not satisfy a preference.

iOS platform conventions and native APIs come first: SwiftUI by default, UIKit only for interactions SwiftUI can’t carry, and Dynamic Type honoured rather than worked around.

.specify/memory/constitution.md § I

Every exception creates system debt. Use semantic tokens and shared foundations instead of one-off values.

Never hardcode a colour, hex, spacing, font or radius — use HHColors, HHSpacing, HHFont, HHRadius. Read colours through .color, since a hex pair silently drops alpha.

New patterns are a last resort. Reuse, refactor, or reject before creating something new.

Every new top-level type gets its own file named for it, so a component stays findable instead of buried in a file that already does three other things.
